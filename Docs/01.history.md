# 项目历史与经验

## 初始基线

- 项目目录原先只有 `Docs/02.orchestrator-implementer-architecture.md`，没有 Git 仓库，也没有游戏代码。
- 已初始化 Git，避免后续无法审查真实 diff 或回退。
- OpenCode 可用模型标识为 `opencode/deepseek-v4.1-flash-free`，与用户指定的 DSV4.1 Flash 对应。
- 架构强调“先读 diff、再独立验证、最后读报告”，后续 Review 必须按此顺序执行。

## [Orchestrator]

- 设计阶段先确认了范围、视觉方向和技术方案，避免 Implementer 在手机优先与桌面布局之间自行猜测。
- 将“开始/重开后焦点移回棋盘”和空格键 `' '`/`Space` 兼容写入契约，提前消除键盘失效风险。
- 设计规格与实施计划分别保存，计划以 TDD 步骤和可复现命令约束 Implementer。
